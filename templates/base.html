Write the header, navigation and footer once here instead of copying them into every page. Two things this file demonstrates for the assignment: 1. {% load static %} at the very top, then {% static 'css/unopsis.css' %} for the stylesheet and {% static 'img/unopsis-logo.svg' %} for the logo. Django builds the address from STATIC_URL, so the path is never hard-coded and the hashed, cache-busted filename is picked up automatically in production (ManifestStaticFilesStorage). 2. Every navigation link is {% url 'route-name' %}, never "/insights/". The address lives in unopsis/urls.py; this file only knows the name. Change a path there and every link here follows. 3. Assignment 5: the navigation is split in two by {% if user.is_authenticated %}. Logged out, the bar carries Home and nothing else, plus Log in and Sign up on the right. Logged in, every protected section appears, plus the signed-in username and a Log out button. The footer links are inside the same test -- easy to miss, and a footer link to /insights/ on a logged-out page is just as much of a tell as a nav link. To be clear about what this is and is not: hiding a link is NOT what protects the page. The protection is @login_required / LoginRequiredMixin in unopsis/views.py, and typing the address by hand still ends at the login page. Hiding the links is about not showing a stranger the shape of a private system, and about not handing a signed-out user a menu of seven things that will all bounce them to a login form. `user` is in every template's context for free because of the django.contrib.auth.context_processors.auth entry in settings/base.py. For an anonymous visitor it is an AnonymousUser, whose is_authenticated is False -- not missing, False -- which is why the test can be written positively and never needs a {% if user %} guard.
