{% extends "base.html" %} {% comment %} The log-in page, served at /accounts/login/ by UnopsisLoginView (unopsis/auth_views.py). Why this file exists at all. django.contrib.auth.views.LoginView already does everything on the server; what it does NOT ship is a template -- Django's own registration/login.html belongs to the admin and looks like the admin. "Custom login page" in the assignment means this: our frame (base.html), our panel/section-title/btn classes, our words. The form is rendered field by field rather than with {{ form }}, for the same reason the create form on brief_detail.html is: {{ form }} emits a and ignores every Bootstrap class, so the page ends up looking like two different websites stacked on top of each other. Two details that are easy to get wrong and expensive to debug: {% csrf_token %} without it Django answers the POST with 403 and no form error, which reads exactly like "wrong password" and is not. the hidden `next` LoginView puts the ?next= it was called with into the context. Passing it back through the POST is what sends somebody who asked for /reports/, got bounced here, and signed in, on to /reports/ rather than to the home page. Without this line the redirect silently forgets. {% endcomment %} {% block title %}Log in{% endblock %} {% block content %}
