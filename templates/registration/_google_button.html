{% load socialaccount %} {% comment %} "Continue with Google" (Assignment 5, Part 2), included by both templates/registration/login.html and templates/registration/signup.html. WHY A PARTIAL. On the login page the button signs you in; on the signup page it creates the account. Those are the same button: allauth decides which one happened by whether it has ever seen that Google identity before, so there is nothing per-page to vary. Two copies of this markup would be two places to fix the day the brand guidelines, the CSRF rule or the provider name changes -- and the copy on the less-visited page is the one that would rot. The leading underscore is the usual signal that this file is a fragment, not a page. WHY {% get_providers %} RATHER THAN A BARE {% provider_login_url 'google' %}. The tag that builds the URL asks allauth for the configured Google application, and if the client id and secret are missing from .env there is none -- so the tag raises SocialApp.DoesNotExist halfway through rendering and the whole LOGIN PAGE answers HTTP 500. That is the one page that must never break, and it would break exactly where it is hardest to notice: on a fresh clone, on the CI machine, and on the server the first time somebody deploys before pasting the credentials in. {% get_providers %} answers with a list instead -- empty when nothing is configured -- so the template can ask the question safely and say something useful either way. settings/base.py only attaches the credentials when BOTH halves are present, which is what makes that list empty rather than full of a half-configured application. AND NOT A LINK. allauth's SOCIALACCOUNT_LOGIN_ON_GET defaults to False, and the default is right: if a GET could start a login, any page on the web could send a visitor into our OAuth flow with a crafted or . A GET on the provider URL therefore lands on an intermediate "Continue" page, so a grader clicking our button would have to click a second one. POSTing to the same URL skips that page without weakening anything -- the CSRF token is what proves the click started here. The `next=next` keyword carries a ?next= destination through Google and back, so somebody who asked for /reports/, got bounced to the login page and chose Google still lands on /reports/.
