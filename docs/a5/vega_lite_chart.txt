 HOW TO USE THIS FILE
 --------------------
 1. Open https://vega.github.io/editor/#/edited
 2. Copy ONLY the JSON between the two "COPY" markers below (block A, or block B for a
    local server). The lines you are reading now are NOT JSON -- pasting them too will
    make the editor report a parse error on line 1.
 3. In block A, replace the single placeholder

        <your-pythonanywhere-domain>

    with the real deployed host, so that data.url reads, for example,
    https://unopsis.pythonanywhere.com/api/insights/items-by-lane/
    That placeholder is the ONLY edit the spec needs. It appears exactly once.
 4. Press "Run". Three bars appear: Needs you / Moving without you / FYI.

 WHY data.url AND NOT INLINE DATA
 --------------------------------
 There is no "values" array anywhere in this file on purpose. The chart fetches the rows
 over HTTP from the live site every time it is run, so it is drawn from whatever is in the
 production database at that moment -- not from a snapshot pasted into the spec.

 WHAT THE ENDPOINT ACTUALLY RETURNS (checked against the running server, not assumed)
 ------------------------------------------------------------------------------------
 A BARE JSON ARRAY -- the top level is a list, not an object wrapping a list. That matters:
 because it is a bare array, the spec needs NO "format": {"property": "..."} clause. If the
 response were {"results": [...]}, this spec would have to say
 "data": {"url": "...", "format": {"property": "results"}} and would otherwise draw nothing.

     [
       {"lane": "needs_you", "label": "Needs you",          "total": 5},
       {"lane": "moving",    "label": "Moving without you", "total": 1},
       {"lane": "fyi",       "label": "FYI",                "total": 1}
     ]

 Field names used in the encoding below, and they are exactly the three keys above:

     label   string   the human-readable lane name  -> x axis
     total   number   how many brief items are in it -> y axis
     lane    string   the machine lane code          -> color + tooltip

 A field name that does not match a real key does not raise an error in Vega-Lite; it
 silently renders an empty chart. unopsis/tests.py (VegaLiteSubmissionTests) reads THIS
 FILE, pulls the field names out of the encoding, and asserts each one is a key the live
 view returns -- so the two cannot drift apart without the test suite failing.

 ONE NOTE ON ACCESS
 ------------------
 /api/insights/items-by-lane/ is the one endpoint of this project that needs no login, and
 the server sends "Access-Control-Allow-Origin: *" with it, which is what allows the editor
 at vega.github.io to read it from another origin. Every other JSON endpoint in the project
 (/api/items/, /api/insights/, /api/insights/messages-by-hour/, the exports) requires a
 session and answers an anonymous request with a 302 to /accounts/login/.

 "sort": null on x and on color is deliberate: it tells Vega-Lite to keep the order the API
 sent (Needs you -> Moving -> FYI, the product's own priority order) instead of re-sorting
 the categories alphabetically, which would put FYI first and read as if it mattered most.
